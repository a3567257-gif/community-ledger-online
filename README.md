# 社區AI帳房 線上版 v1.0.0

社區管理費記帳系統的線上版，給**物業管理公司**一次管理多個社區使用。帳務邏輯（FIFO 沖帳、虛擬帳號比對、民國年日期、期別與結算日、復原匯入、月結報表）直接沿用離線版 v3.0.1，已經用測試確認兩邊算出來的帳完全相同。

離線版原始碼在 `打包\claude\離線版社區AI帳房\社區帳房-v10原始碼\community-ledger\`，線上版不會改到它。

## 版本規則

跟離線版一樣：**每次修改並發布新版，版本號第一個數字加 1**（v1.0.0 → v2.0.0 → …）。版本號改在 `package.json` 的 `version`。

| 版本 | 日期 | 內容 |
|---|---|---|
| v1.0.0 | 115/10/17 | 第一版：離線版 v3.0.1 全部功能搬上線；物業公司 → 多社區帳號架構；後台（社區總覽、帳號、授權期別、操作紀錄）；雲端自動快照 |

## 跟離線版的差別

| | 離線版 | 線上版 |
|---|---|---|
| 資料放哪裡 | 社區那台電腦 | 雲端資料庫（Neon，新加坡機房） |
| 登入 | 選用的管理密碼 | 每個人自己的帳號密碼 |
| 帳號架構 | 一台電腦一個社區 | 樓管家 → 物業公司 → 多個社區；社區經理／秘書只看得到被指派的社區 |
| 授權 | 綁電腦的授權碼 | 後台設定「授權到哪一期」，規則相同（那一期可以做完月結；結帳進入下一期或超過 20 天後變唯讀） |
| 備份 | 每日自動備份到電腦＋隨身碟 | 每天第一次修改後自動快照（保留 60 天）；重要動作前自動快照；可隨時下載備份檔 |
| 操作紀錄 | 無 | 誰、什麼時候、做了什麼，資料庫層面不可修改、不可刪除 |
| 物業公司總部 | 無 | 後台一頁看所有社區：本期、帳款是否產生、欠繳戶數與金額、授權狀態、是否忘了結帳 |
| 示範版 | 另外一個安裝檔 | 後台新增社區時選「示範」，有「還原成示範資料」和示範檔案下載 |

## 身分

| 身分 | 誰 | 可以做什麼 |
|---|---|---|
| 樓管家管理者 | 系統提供者（你） | 全部：新增物業公司、社區、設定授權期別、管理所有帳號 |
| 物業公司管理者 | 物業公司總部 | 看自己公司所有社區、進入任一社區記帳、新增／停用自己公司的社區經理帳號 |
| 社區經理／秘書 | 做帳的人 | 只能進入被指派的社區記帳 |

## 在自己電腦上執行（開發、測試）

需要 Node.js 20 以上。不用安裝資料庫：沒有設定 `DATABASE_URL` 時，會用內建的資料庫存在 `local-data` 資料夾。

```bash
npm install
```

```bash
npm start
```

然後打開 http://localhost:3210。第一次啟動會用 `.env` 裡的 `ADMIN_LOGIN`／`ADMIN_PASSWORD` 建立最高管理者帳號，並建立一個示範社區（幸福花園社區，36 戶虛構資料）。`.env` 的範例在 `.env.example`。

想從頭開始：關掉伺服器，刪除 `local-data` 資料夾，再啟動一次。

## 測試

```bash
npm test
```

- `test/core.golden.test.js`：用示範社區把整個流程跑一遍（匯入未繳／預繳、產生帳款、銀行沖帳、人工指定、年繳優惠、重複匯入阻擋、復原匯入、結帳、空白社區開帳），比對線上版和離線版的結果必須**完全相同**。找不到離線版原始碼時會自動略過。**改到帳務邏輯（`server/core/store.js`）時一定要跑。**
- `test/api.test.js`：登入、不同公司看不到彼此的社區、授權到期變唯讀、上傳下載、快照還原、操作紀錄不可修改。

## 部署到雲端（免費方案：Render + Neon）

需要三個帳號（都可以免費註冊、不用信用卡）：GitHub、Neon、Render。帳號要由你自己註冊。

1. **GitHub**：建立一個**私人（Private）**儲存庫，把這個資料夾推上去（`.env`、`local-data` 不會上傳）。
2. **Neon**（資料庫）：建立專案，區域選 **Singapore**，複製「Connection string」（`postgresql://` 開頭，含 `sslmode=require`）。
3. **Render**（網站）：New → **Blueprint** → 選 GitHub 儲存庫，Render 會讀 `render.yaml`。填入：
   - `DATABASE_URL`：Neon 的連線網址
   - `ADMIN_LOGIN`、`ADMIN_PASSWORD`：你的最高管理者帳號密碼（密碼至少 8 個字元）
   - `SESSION_SECRET` 會自動產生
4. 部署完成後打開 Render 給的網址（`https://….onrender.com`）登入，到「後台管理」新增物業公司、社區、帳號。

之後每次修改程式，推到 GitHub 後 Render 會自動重新部署，資料庫的資料不受影響。

### 免費方案的限制

- 網站 15 分鐘沒人用會休眠，下一次打開要等 30～60 秒。展示前先打開一次。
- 有第一個付費社區時：Render 改成 Starter（約 US$7／月，不休眠）；Neon 升級成有較長還原期限的方案。
- 程式只用標準 Node.js + PostgreSQL，以後要搬到其他主機（例如 Zeabur）不用改程式。

## 資料與個資

- 住戶資料（戶號、虛擬帳號、繳費紀錄）存在 Neon 的新加坡機房，傳輸全程加密（HTTPS、資料庫 SSL）。
- 跟物業公司簽約時，合約要寫明資料存放位置、備份方式、合約結束後資料怎麼交還（社區可以隨時從「備份・帳號」頁下載完整資料）。
- 密碼用 scrypt 雜湊儲存；登入失敗限速；12 小時沒操作要重新登入；改密碼或停用帳號會讓其他裝置的登入立即失效。

## 程式結構

```
server/
  index.js          伺服器進入點（安全標頭、登入 cookie、路由）
  db.js             資料庫連線（雲端 PostgreSQL／本機 PGlite）
  auth.js           密碼、登入、權限
  ledger.js         把資料庫裡的社區資料接上帳務邏輯；修改時排隊、交易、快照、操作紀錄
  routes/
    account.js      登入、登出、變更密碼
    community.js    社區帳務 API（對應離線版 main.js 每一個功能）
    admin.js        後台
  core/             帳務邏輯，沿用離線版
    store.js        離線版 store.js，只改了資料存取方式
    fifo.js period.js report.js   跟離線版 shared/、report.js 相同
    excel-read.js   讀上傳的 Excel（離線版讀檔案路徑）
    license.js      授權期別判斷（規則跟離線版相同，拿掉機器碼）
  db/schema.sql     資料表
  db/bootstrap.js   第一次啟動建立管理者與示範社區
public/             畫面（index.html、app.js 沿用離線版；api-web.js 取代離線版 preload.js）
assets/             Excel 範本、示範檔案、示範社區資料
test/               測試
```

### 每個社區的資料怎麼存

每個社區的帳務資料是一份 JSON（`community_data.doc`），格式跟離線版的 `community-ledger-data.json` 完全相同，所以：

- 離線版的備份檔可以直接用「上傳備份檔還原」匯入線上版（離線版社區要改用線上版時就這樣搬）。
- 線上版下載的備份檔，也可以在離線版「還原其他備份檔案」使用。
